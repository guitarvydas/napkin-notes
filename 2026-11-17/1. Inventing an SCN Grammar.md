This video is part 18 of a train of thought on how to port the PBP kernel to C https://youtu.be/hC7Oazr3kuw. 

It contains a significant *AHA* moment. I invent a simple little SCN (a tiny DSL) to describe the code I want. 

I'm trying to solve the problem of how to inhale a 2,000 line JSON file generated from the PBP kernel diagram.

I end up with an 11 line grammar that seems to do the job. I develop and test the grammar using [Ohm-editor](http://ohmjs.org). From experience, I feel that I will be able to generate Python and C code from this - we'll see.

This doesn't solve the whole problem of porting the kernel to C. It is only an attack at a sub-problem - how to inhale a regular, restricted JSON file and convert it to some internal data structures. In this video, I'm only dealing with a sub-sub-problem - how to read the JSON file. Once I can do that, it "will become obvious" how to generate internal data structures from the pattern match ("parse").

I make a few concession to simplicity and parseability and compose an SCN (tiny DSL) that meets the needs of parsing the full-blown problem AND is a subset of OhmJS. This means that I can use Ohm-editor to invent and check the SCN syntax. I don't have to build code to check my work - I just buy in a checker (OhmJS).

This video shows the grammar and its testing. The grammar I need is only 11 lines long, but parses some 2,000 lines of kernel.drawio.json.

Kernel.drawio.json is very regular, since it is generated by a program (das2json). I can cut a lot of corners, and, if I stop myself from generalizing, I get an acceptable, but very small, grammar - 11 lines.
