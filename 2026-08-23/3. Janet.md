Janet is **homoiconic**. Its programs are represented using the same fundamental data structures that the language manipulates—lists, symbols, numbers, etc.—much like Lisp.

For example, Janet code such as:

```janet
(+ 2 (* x 3))
```

can be represented/manipulated as Janet data, and Janet provides facilities for reading and evaluating code.

So, in the context of your previous question:

- **Lua:** not homoiconic, but `load()` lets you generate source and compile it at runtime.
    
- **Janet:** homoiconic; you can construct/manipulate the program as data directly, without first converting your AST to source text.
    
- **Common Lisp/Scheme/Clojure:** similarly homoiconic Lisp-family approaches.
    

And Janet is particularly interesting if you're looking for a **small Lisp that can be embedded and used as a metaprogramming substrate**.

---
> I think that Janet has PEG built into it?

Yes — **PEG is built into Janet**, and it's one of the things that makes Janet particularly interesting for the sort of language/metaprogramming work you've been discussing.

Janet's standard/core library includes a **PEG (Parsing Expression Grammar) module**, with functions such as:

```janet
peg/compile
peg/match
peg/find
peg/find-all
peg/replace
peg/replace-all
```

The Janet documentation explicitly lists **“Parsing Expression Grammars built in to the core library.”** ([Janet](https://www.janet-lang.org/1.16.1/index.html?utm_source=chatgpt.com "Janet Programming Language"))

### And PEG is used for Janet itself

This is especially interesting: Janet's own syntax is described by a PEG grammar in its documentation. The Janet parser turns source text into Janet data structures, and because Janet is homoiconic, that data structure can then be manipulated by macros/compiler code. ([Janet](https://www.janet-lang.org/1.16.1/docs/syntax.html?utm_source=chatgpt.com "Syntax and the Parser"))

So there's a rather nice pipeline:

```text
       source text
            │
            ▼
       Janet PEG/parser
            │
            ▼
       Janet data
       (AST-ish)
            │
            ▼
          macros
            │
            ▼
         compiler
            │
            ▼
       Janet bytecode
```

And PEG isn't merely an external parsing library. The implementation can be compiled out with `JANET_NO_PEG`, which confirms that it's an integrated module in the Janet implementation. ([Janet](https://www.janet-lang.org/1.16.1/capi/configuration.html?utm_source=chatgpt.com "Configuration"))

### This makes Janet unusually attractive for your purposes

You were asking earlier about using Lua as a substrate:

```text
your language
      ↓
 generate Lua source
      ↓
    load()
      ↓
 executable Lua
```

With Janet you have a much richer set of pieces available:

```text
             your syntax
                  │
                  ▼
             Janet PEG
                  │
                  ▼
          Janet data structures
                  │
          ┌───────┴───────┐
          ▼               ▼
       transform        macro
          │               │
          └───────┬───────┘
                  ▼
             Janet compiler
                  │
                  ▼
             executable
```

And because the intermediate representation is **ordinary Janet data**, you don't have to serialize your AST back into text just to get it compiled.

That's a significant difference from the Lua approach.

For something like your **diagram-as-syntax / 0D work**, I'd consider Janet a particularly interesting target: **PEG + homoiconicity + macros + a small embeddable implementation** is a very potent combination. The Janet project describes the entire language, including its interpreter, compiler, assembler and PEG implementation, as less than 1 MB. ([Janet](https://www.janet-lang.org/1.16.1/index.html?utm_source=chatgpt.com "Janet Programming Language"))
