Languages that can create itself or other languages:
1. homoiconic (e.g. Lisp) means that the source code of the language is represented in a form that the language can manipulate. Lisp does this by storing its source code as _lists_ (on disk, the lists are written out as text, but, at runtime, the code is made up of lists)
2. any language that supports _eval()_ (e.g. Javascript (!))
3. `/bin/*sh` (e.g. /bin/bash) - has the advantage that it also supports multiple simplifying assumptions (aka "spherical cows") - you don't have to stick to only one language (it's a better workflow than the 1960s idea of using only a single language for the whole of your programming workflow for a project). For example, parts of some problems are better solved with relational thinking, e.g. something like Prolog (datalog, miniKanren, etc.) but using _only_ relational thinking tends to complexify other parts of a project
4. using [OhmJS](ohmjs.org) (a successor of PEG parsing) coupled with rewriting (or just dealing with strings in JS "semantics" code for OhmJS) e.g. [experiments with text to text transpilation](https://programmingsimplicity.substack.com/p/experiments-with-text-to-text-transpilation?r=1egdky)
