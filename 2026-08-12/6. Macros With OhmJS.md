# Macros With OhmJS
2026-08-12

## grammar
```
macro {
  main = stuff+
  stuff = 
    | applySyntactic<HamburgerAndFries> -- macro
    | any -- other
  HamburgerAndFries = "hamburger" "and" "fries"
}
```

"ApplySyntactic<...>" is unique to OhmJS. A capitalized rule skips spaces automagically. You can't use a syntactic rule (capitalized) within a lexical rule (non-capitalized) unless you specify `applySyntactic<...>`.

The parser looks for "hamburger and fries" with any number of spaces and newlines in between the words - i.e. a syntactic rule.

## test
```
a b c hamburger and bacon d e f hamburger and fries g h i
```

This test shows that "hamburger and bacon" is rejected as a macro pattern . The parser sees only "hamburger and fries" as a macro pattern. Everything else is a "stuff_other", parsed character by character - wildly inefficient by 20th century standards, but quite reasonable using 21st century hardware. (Not reasonable for production code, but, macros are used for development code, wherein the definition of "efficiency" is different from what we've been led to believe by 20th century biases)

What happens to the macro match depends on the semantics code attached to that grammar rule ("stuff_macro"). The simplest thing to do is to simply rewrite it as a different string. That's what T2T (using `.rwr` rules) does...
