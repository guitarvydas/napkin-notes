Here is something that I'm pondering - comments welcome.

_Something_ in the early days of programming (e.g. Rebol, Forth, assembler, etc.) produced code that is orders of magnitude smaller than what is currently accepted as the norm.

- synchronous, sequential stance
	- strong coupling
	- allows only one kind of architecture
	- cannot directly express asynchronous concurrency
- syntax-directed action vs. computation
	- computation-based parsing produces a data structure (a pruned AST called a CST) that is later walked and acted upon, whereas Rebol, Forth, S/SL, Prolog allow actions to fire while parsing

Is the cost of disallowing side-effects memory footprint size?

Do we need to "compile" computation into side-effectful assembler?

Can we figure out a safe way to fold actions and side effects together with computational expression? Can we compile away the intermediate data structure (CST/AST)?
