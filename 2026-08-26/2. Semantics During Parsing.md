I think those are all syntactic differences.

Rebol "parse" also has a semantic difference.

With PEG, the parser constructs a (concrete) parse tree, then walks the tree firing actions that hang off of the tree like ornaments on a Christmas tree. Most PEG syntaxes require you to physically put the ornaments on the tree (Ohm doesn't - you write grammar in one place and put the semantics (ornaments) in another place - the tree nodes are connected to the ornaments by name (each semantic action has a name derived from the grammar rule)).

In Rebol parse, though, semantic actions fire right away during the parse. There is no need to construct a tree data structure. S/SL does the same, too, and results in much smaller executables.

This particular example doesn't matter if the parse tree is never built in shipped, production code. Developers buy big machines with lots of memory, so generating a tree at compile time is reasonable. The compilation step is done only on dev machines and is not included in production code shipped to users.

This is but one difference, but, we know that Rebol code is smaller and packs a lot of punch in production.
