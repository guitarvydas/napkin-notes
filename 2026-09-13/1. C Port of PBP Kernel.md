# C Port of PBP Kernel
2026-09-13
I've begun an experiment to port the PBP kernel to C.

The challenge is that the kernel is currently written assuming the use of dynamically typed languages. 

The kernel source code (`*.rt` in [pbp kernel](https://github.com/guitarvydas/pbp/tree/c_type_annotations/kernel) branch `c_type_annotations`) currently contains no type annotations. 

I think that inserting type annotations into source code results in messy, unreadable code. Type annotations are useful for Production Engineering, but are essentially line noise for Design Engineering. It was necessary in the 20th century to conflate programming language syntax with type annotation syntax, because building languages was considered difficult and time consuming, but, in the 21st century it is much easier to build little languages and, maybe, we can finally break this habit.

I've been trying to capture my progress in a Twitch-like manner in a [YouTube playlist](https://www.youtube.com/playlist?list=PLLklGkLmCilw). I started by recording everything but have switched to making shorter videos after part 3.

Part 7 is the beginning of today's sub-experiment. I intend to process the existing kernel source code and produce a "form" which leaves indicators of where I need to manually supply types. 

In the future, it might be possible to use type inferencing, say using Prolog or miniKanren, to fill in some of the information, but, for now, I'll just enter the information manually, to keep things simple and do-able. 

This is an ongoing experiment. One possible result of this line of experimentation might be that I find the task of porting - this way - to C to be impossible. We'll see. I'm using the interim results for brainstorming the next steps.
