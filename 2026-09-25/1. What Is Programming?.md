I hear the word "programming" through my own filter.

Programming is the act of getting things done by writing sequential instructions meant for scripting the actions of reprogrammable electronic machines, i.e. "computers".

Note the plural form of "machines" in the above.

A _single_ sequential machine cannot run parallel tasks in parallel - ever.

Parallel tasks are asynchronous. Asynchronous is the opposite of synchronous. Asynchronous and synchronous are not on the same continuum.

This means, that if you use a sequential, synchronous programming language - i.e just about every language we have today - you _cannot_ express parallelism, you can only _simulate_ parallelism. Regardless of how you warp the meaning of the word "concurrency". You can use syntactic baubles like "async/await" to express at a very low assembler-like level, the concept that your synchronous code will wake up and do something when some essentially random outside event occurs. This expresses what your closed-world node does when an asynchronous event occurs, but, does not express what the outside world is doing, from where the event originated. There is no way to use a synchronous notation to describe asynchronous (parallel) activity.

An example: a musical score. A score is a notation that expresses how to synchronize various instruments in an orchestra. Each staff (or pair of staffs) on the score represents a different instrument. A conductor needs to synchronize all of the instruments in the orchestra to play together. When the orchestra is just learning the piece, the instruments tend not to be well synchronized. A synchronous programming language cannot express this state of pre-perfection. In fact the score itself can only express the ultimate perfect state of the music - it does not express pre-perfection, nor the addition of human emotion and nuance in a performance.
