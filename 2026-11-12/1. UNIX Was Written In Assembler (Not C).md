# UNIX Was Written In Assembler (Not C)

2026-11-12

Contrary to what I've been told for decades, UNIX was first written in assembler, not C.

V4 was the first version of UNIX ported to K&R C.

[Brian Kernighan: Inside Bell Labs, The Best Programmer, Why C Won](https://youtu.be/sMllOlxVgD0?t=1757)

[TUHS](https://www.tuhs.org/cgi-bin/utree.pl)

# IMO
Many great ideas were first implemented in assembler, e.g. UNIX, VisiCalc, Sketchpad, Turbo Pascal, Lisp, etc.

I conclude that the way we write code now - using functions and calling conventions - tends to restrict our inventiveness. 

There are other ways to write code - Prolog and Forth and assembler are obvious examples. Electronics hardware is a completely different approach - ICs are isolated and asynchronous, whereas software functions are synchronous and sequential. See the original form of [Atari Pong](https://www.reddit.com/r/EngineeringPorn/comments/ul49zt/the_original_pong_video_game_had_no_code_and_was/). The schematic[^2] for Pong fit on one large piece of paper.

Casting everything into functions has its uses, but this approach hits an asymptote on usability, after which point we must expend brain power to distort[^1] our problems into functional/computational form while discarding anything that doesn't fit that paradigm.

What I favour is a way of creating software using recursive, soft schematics, which I call PBP (Parts Based Programming).

[^1]: This used to be called "epicycles".
[^2]: Electronics schematics have problems, but, expressing designs composed of asynchronous components is not one of the problems.
